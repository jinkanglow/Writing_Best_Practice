# v10.1 editorial orchestration

Run `node scripts/editorial-orchestration.js audit examples/intelligence/orchestration.json`. The synthetic incomplete fixture intentionally exits 4. Redirect stdout to a report and use `verify INPUT REPORT` to recompute it. Exit 2 indicates invalid input.

Inputs: text, v10.0 plan, evidence and release (the existing unified release input). CLI loads repository policies. Evidence.support maps claim IDs to source IDs to exact quote objects. Evidence.artifacts maps contribution IDs to content and SHA256 hash. First audit returns candidate IDs and basis. An editor records evidence.review with basis, author, reviewer, candidates (kind, reason, claimIds), entailment (claim/source keyed decision and reason), lineage (source keyed decision, reason, normalized contentHash), contributions (decision, reason, artifactHash), findings (decision, reason), and progression (decision, reason). Candidate decisions distinguish claim and nonclaim. Entailment must be supports; lineage and contributions must be confirmed. Findings must be acknowledged; progression approved. Recompute after changes. Existing v10.0 review and legacy release checks remain mandatory. Release requires workflow, evidence, coverage, coherence and structure when a baseline exists, plus the legacy gate.

Sentence extraction is heuristic, not a semantic model; abbreviations and decimals can split candidates. Exact quotes and artifact hashes establish local consistency only. Identical normalized root content is flagged, not proof of independent reporting. Review identities are self-declared. No external verification or publication authorization is implied. No independent blind evaluation has been conducted.
